# Clips Cloud API (клиентский контракт)

Статус: черновик контракта для бэкенда. Клиентская часть реализована в
`src/features/clips/` (типизированный клиент `api.ts`, локальный реестр
`registry.ts`, правила спойлеров/«Лучших моментов» `helpers.ts`) и в
расширении плеера `extensions/capture.tsx` + `extensions/bestMoments.tsx`.
Публичная страница шеринга: `https://seans.tedeshi.ru/c/<code>`.

Общее:

- Base URL: `https://api.seans.tedeshi.ru` (как у основного API приложения).
- Авторизация: `Authorization: Bearer <JWT>` (как в `src/api/session.ts`).
  Токен хранится в Credential Manager / памяти, в localStorage не пишется.
- Тела ответов — JSON в snake_case (клиент толерантен и к camelCase).
- Short code: 8 символов `[a-z0-9]`, уникален, генерируется сервером.
  Клиент генерирует такой же код локально для pending-записей и заменяет
  его серверным после загрузки.
- Клип = вырезка A→B исходного видео. Скриншот = один кадр. Скриншоты
  участвуют в тех же схемах загрузки/видимости/спойлера, но НЕ показываются
  в «Лучших моментах» (ни после фильма, ни в карточке).

## Ресурсы

### POST /api/clips — загрузка клипа

`multipart/form-data`, две части:

| часть | тип | описание |
|---|---|---|
| `file` | binary | файл клипа (mp4/mkv, stream-copy вырезка) |
| `meta` | `application/json` | метаданные, см. ниже |

`meta` (snake_case):

```json
{
  "media_id": "123",
  "start_sec": 12.5,
  "end_sec": 45.0,
  "title": "необязательный заголовок",
  "spoiler": false,
  "visibility": "by_link"
}
```

- `media_id` (string) — id фильма/сериала в API Seans.
- `start_sec`, `end_sec` (number, ≥ 0, `end_sec > start_sec`) — таймкоды в
  исходнике (клип может начинаться с ближнего keyframe).
- `title` (string, опц.) — задаётся пользователем.
- `spoiler` (bool, default `false`) — флаг спойлера.
- `visibility` (`closed|by_link|open`, default `closed` на сервере; клиент
  по умолчанию шлёт `by_link`).

Ответ `201` (или `200`) — запись клипа:

```json
{
  "id": "cl_01H…",
  "code": "a1b2c3d4",
  "url": "https://seans.tedeshi.ru/c/a1b2c3d4",
  "visibility": "by_link",
  "spoiler": false,
  "created_at": "2026-11-17T12:00:00Z",
  "media_id": "123",
  "start_sec": 12.5,
  "end_sec": 45.0,
  "title": null,
  "file_url": "https://cdn.seans.tedeshi.ru/clips/cl_01H….mp4"
}
```

- `url` — публичная страница шеринга.
- `file_url` — прямая ссылка на медиафайл (для стриминга клипа в плеере;
  при `visibility=closed` должна требовать авторизацию или отдаваться
  подписанным URL с коротким TTL).

### POST /api/screenshots — загрузка скриншота

Тот же multipart-формат (`file` + `meta`):

```json
{
  "media_id": "123",
  "at_sec": 88.2,
  "spoiler": false,
  "visibility": "by_link"
}
```

Ответ — та же форма записи, но без `start_sec`/`end_sec` (есть `at_sec`);
`file_url` указывает на изображение.

### PATCH /api/clips/{id} и PATCH /api/screenshots/{id}

Тело (оба поля опциональны, хотя бы одно):

```json
{ "visibility": "open", "spoiler": true }
```

Ответ `200` (пустое тело или запись — клиент не требует тела).

### GET /api/clips?media_id=…

Список клипов фильма. Правила отдачи:

- без авторизации / с чужим токеном — только `visibility=open`;
- с токеном владельца — свои клипы любой видимости + чужие `open`.

Фильтр `spoiler` сервер НЕ применяет — клиент скрывает спойлеры от тех, кто
фильм не досмотрел (см. «Спойлеры» ниже).

Ответ:

```json
{ "items": [ { …запись клипа… } ] }
```

(Допускается и голый массив; клиент принимает `items`, `clips` или массив.)

Аналогично может существовать `GET /api/screenshots?media_id=…`; клиент
пока его не вызывает (скриншоты видны только в реестре плеера).

### GET /api/c/{code} — публичный доступ по ссылке

- `visibility=by_link|open` — доступ всем, без авторизации.
- `visibility=closed` — только `Authorization` владельца; чужой/анонимный
  запрос → `403` (или `404`, чтобы не раскрывать существование — на выбор
  сервера, клиент принимает оба).

Ответ — запись клипа/скриншота (включая `file_url`), при успехе.

### DELETE /api/clips/{id}, DELETE /api/screenshots/{id}

Удаление своей записи. `204`/`200` при успехе.

## Статусы ошибок

| код | когда | поведение клиента |
|---|---|---|
| `401` | нет/просрочен JWT | toast «нужна авторизация», файл остаётся локально («Ожидает загрузки») |
| `403` | чужой ресурс / closed без прав | toast, локальная запись не удаляется |
| `404` | нет записи/кода | `getByCode` → `null`, DELETE идемпотентен |
| `413` | файл больше лимита | toast «файл слишком большой», запись `failed` |
| прочие `4xx/5xx` / сеть | сервер недоступен | graceful degradation: запись `pending`/`failed`, кнопка «Загрузить» повторяет |

Все ошибки клиент парсит в `{code, status, message}` (`clips/api.ts`);
ни одна ошибка не роняет плеер и не блокирует экспорт/скриншот.

## Спойлеры

- Флаг `spoiler` хранится на сервере (запись) и локально (реестр).
- Скрытие контента — на клиенте: спойлер виден только тому, кто фильм
  досмотрел. Признаки «досмотрел»:
  1. локальный флаг `seans.watch.<media_id>` (выставляется, когда плеер
     дошёл до eof — см. `helpers.ts: markMediaWatched`);
  2. прогресс истории: `completed=true` либо
     `position_sec / duration_sec >= 0.95` (общее правило
     `historyThrottle.COMPLETED_RATIO`).
- Применяется в карточке фильма («Лучшие моменты») и в подборке после
  фильма.

## Видимость

| значение | доступ по ссылке | карточка фильма |
|---|---|---|
| `closed` | только владелец (JWT) | нет |
| `by_link` | все, у кого есть ссылка | нет |
| `open` | все | да (с учётом спойлера) |

Переключатель видимости есть у каждого клипа/скриншота в плеере (меню
«Захват» → «Облако»); PATCH уходит на сервер, локальная копия обновляется
сразу.

## Локальный реестр (клиент)

`localStorage`:
- `seans.player.ext.capture.cloud.clips` — JSON-массив клипов,
- `seans.player.ext.capture.cloud.screenshots` — JSON-массив скриншотов.

Запись = `LocalCloudAsset` (`src/features/clips/types.ts`): `localId`,
`kind`, `mediaId`, `title`, `spoiler`, `visibility`, `status`
(`pending|uploading|uploaded|failed`), `error`, `localPath`, `startSec`,
`endSec`, `atSec`, `id`, `code`, `url`, `fileUrl`, `createdAt`, `updatedAt`.
Нужен UI-слою плеера (статус загрузки, «Загрузить»/«Поделиться») и подборке
«Лучшие моменты» (локальный файл важнее облачной ссылки).

## «Лучшие моменты» (после фильма)

Не серверный эндпоинт — клиентская подборка:

- Источник: локальный реестр + (в перспективе) `GET /api/clips?media_id=…`.
- Только клипы (`kind=clip`), скриншоты исключены.
- Сортировка по `start_sec` (клип финала не идёт раньше клипа начала).
- Спойлеры — по правилам выше (после eof зритель считается досмотревшим).
- Воспроизведение: локальный файл, если он ещё существует
  (`capture_file_exists`), иначе `file_url` (стрим).

## Известные ограничения / находки ревью (к сведению бэкенда и доработкам)

1. Лимит размера файла (`413`) клиент обрабатывает только тостом —
   сжатие/резка на части не реализованы.
2. Резюме загрузки (resumable upload / tus) нет: повтор — полная перезаливка.
3. `file_url` для `closed`-записей — вопрос подписанных ссылок/TTL (см. выше),
   клиент просто отдаёт URL в плеер.
4. `GET /api/screenshots?media_id=…` контрактом предусмотрен, клиентом пока
   не вызывается.
5. Фиксы экспорта из ревью PR #65 (проверка кодеков `-c copy` для MP4,
   проверка артефакта после ffmpeg, прогресс `out_time_ms=`) — в отдельном
   PR #77 (`fix/issue-76-capture-export`), в эту ветку НЕ переносились и
   считаются закрытыми там. Клиентский guard повторного экспорта/снимка и
   единый штамп имён у fallback-кадров — в этой ветке.
