# Мини-плеер поверх других приложений

Задача: [#24](https://github.com/seans-ru/client/issues/24). Ветка:
`feature/issue-24-pip`. Статус: прототип для ревью.

## Решение и сравнение вариантов

По уточнённому требованию мини-плеер должен работать как PiP в Firefox:
отдельное системное окно поверх других приложений. Выбрано окно Tauri с
`alwaysOnTop: true`, без родительского окна. На Windows owned-окно скрывается
при сворачивании владельца, поэтому связь через `parent` здесь не подходит.

| Вариант | Возможности и цена | Решение |
| --- | --- | --- |
| Overlay внутри приложения | Простое копирование canvas, но скрывается вместе с главным окном и не появляется поверх других программ | Не соответствует уточнённому требованию |
| Отдельное окно Tauri | Настоящее отдельное topmost-окно. Получает готовые кадры через существующий loopback `/frames`; дополнительный mpv, перенос GL-контекста и изменения Rust не нужны. Цена — второй webview, HTTP-подписчик и WebGL-загрузка текстуры | **Выбрано** |
| Windows Compact Overlay | Платформенный компактный режим Windows; потребует отдельной интеграции и всё равно видеоповерхности. Не переносится на остальные платформы | Не выбираем для общей реализации |

## Архитектура

Расширение `pipMiniPlayer` остаётся владельцем жизненного цикла и управления.
Оно открывает единственное окно `player-pip`, а его компонент `PipWindow`
подключается к существующему серверу кадров. Сервер уже поддерживает несколько
независимых подписчиков и отдаёт новому подписчику последний кадр, включая
кадр на паузе. Формат кадров, Rust, mpv-мост и `usePlayer` не меняются.

Второе окно получает собственный `CanvasVideoRenderer`. Оно не монтирует
`App`, авторизацию, обновления или `usePlayer`: его закрытие не вызывает
`player_destroy` и не прерывает основную сессию.

После подключения PiP общий `pipPresentation` передаёт ему видеовывод.
`PlayerSurface` закрывает свой HTTP-поток кадров и освобождает WebGL-рендерер,
скрывает видео, контролы и overlay, отключает локальные горячие клавиши.
В главном окне остаются сообщение и кнопка «Вернуть в основной плеер».
Общая сессия mpv, звук, история и комнатная синхронизация продолжают работать.
После уничтожения окна PiP основной видеовывод подключается снова и получает
последний кадр. Подписки расширений на frameHub сохраняются при временном
переключении; полный сброс выполняется при размонтировании экрана.

RGBA-поток содержит поля, добавленные mpv для размера главного окна.
Расширение читает геометрию `osd-dimensions` через существующий mpv-мост и
передаёт её в PiP при подключении и изменении геометрии (опрос раз в 500 мс).
Canvas масштабируется по области самого изображения; поля главного рендера
выносятся за границы PiP. Внутри мини-окна остаётся только один набор полей,
необходимый при несовпадении пропорций окна и видео. Изображение не искажается
и не обрезается. Поля, закодированные в самом видео, не определяются по цвету
пикселей и остаются частью изображения.

Адрес потока и начальное состояние передаются после запроса готовности окна.
Состояние содержит только время, длительность и паузу. Команды передаются
адресными Tauri-событиями в `main`, где расширение вызывает `ctx.transport`.
Таким образом сохраняются ограничения progressive-перемотки, история и
комнатная синхронизация. PiP не вызывает транспортные команды напрямую.

## Поведение

| Сценарий | Результат |
| --- | --- |
| Открытие | Настройки воспроизведения → «Мини-плеер поверх окон». Повторное открытие не создаёт дубликат. Ошибка создания показывается в настройках |
| Главное окно свёрнуто или закрыто другой программой | PiP остаётся отдельным окном поверх обычных приложений; кадры идут непосредственно из Rust, без копирования из canvas главного окна |
| Закрытие главного окна / источника | Мини-плеер закрывается вместе с владельцем сессии |
| Активный PiP | Основной видеовывод и его управление отключены; сообщение и кнопка возврата остаются доступны |
| Закрытие PiP | Закрывает мини-окно и восстанавливает основной видеовывод на текущей позиции без перезапуска сессии |
| Внешний вид | Окно без системного заголовка и нижней панели. Белый крестик сверху справа. Поверх видео снизу слева — белые SVG-иконки play/pause, −5 с, +5 с без фона; справа — таймбар и текущее время/длительность |
| Масштабирование | Изображение вписывается до краёв окна с сохранением пропорций. При одинаковом соотношении сторон полей нет; при разном — поля только сверху/снизу либо по бокам. После resize используется новая геометрия; устаревшие поля другого размера RGBA-кадра не применяются |
| Управление | Play/pause, −5 с, +5 с и перемотка таймбаром. Клик по свободной области видео — play/pause. Все команды проходят через guarded transport |
| Звук | Одна существующая сессия mpv; второй аудиопоток не создаётся |
| Субтитры | Передаются в составе кадра mpv; выбор дорожки остаётся в главных настройках |
| Перемещение / resize | Перетаскивание за всю свободную область окна, включая верх и поля, после смещения мыши > 4 px; клик без смещения переключает play/pause. Кнопки, таймбар и зоны resize исключены. Resize края/угла идёт с привязкой к пропорциям изображения: одна сторона следует за курсором, вторая — за пропорциями видео, чёрные поля не появляются. Опорный край/угол неподвижен. Позиция и размер сохраняются в физических пикселях. Если сохранённое окно не помещается на подключённых мониторах, используется исходное центрирование |
| Fullscreen | Отдельное PiP-окно сохраняется; поведение поверх эксклюзивного fullscreen других программ определяется ОС |
| Производительность | Один декодер и один рендер mpv. Кадры полного разрешения получает активный видеовывод: основной либо PiP. При передаче в PiP поток и WebGL основного окна останавливаются. Нужен замер CPU/GPU/памяти перед production, особенно для 4K |

Разрешения второго окна ограничены событиями и операциями над окном
(геометрия, показ, закрытие, перетаскивание и resize). Доступ к сетевым плагинам, обновлению и перезапуску ему
не добавляется. Главное окно получает создание webview-окна и закрытие окна.

## Проверки и границы

На Windows вручную подтверждены отдельное окно с изображением, синхронная
перемотка из PiP в основной плеер и новый вид без системной рамки с белыми
контролами поверх видео. `npm run build` (включая typecheck)
прошёл, 43 теста PiP, геометрии, frameHub и реестра расширений прошли.
Автотесты покрывают создание одного окна, передачу команд через guarded
transport, валидацию позиции таймбара и отмену открытия при закрытии источника. `cargo check` остановился
на ошибке установленного Rust toolchain: `only metadata stub found for rlib
dependency core`. Rust-исходники в этой ветке не изменены.

Геометрия проверена автотестами для одинаковых и разных пропорций, вертикального
видео, полей по двум осям и изменения размера исходного рендера. Передача
видеовывода в PiP, отключение основного UI и восстановление на той же позиции
по кнопке возврата проверены вручную в Windows. Автотесты также проверяют
передачу видеовывода только после подключения PiP, возврат после закрытия
окна и восстановление состояния при завершении сессии.

Перед production нужны ревью прототипа, замеры переключения видеовывода,
проверка длительного воспроизведения при свёрнутом главном окне,
смены монитора/DPI, субтитров (включая размещённые в полях mpv), progressive и комнат. macOS/Linux требуют
платформенной проверки после портинга самого backend. Доводка до production
остаётся отдельной задачей после ревью, как предусмотрено в #24.
